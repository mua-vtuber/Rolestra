**R12-C 1차 종결 사정** (사무실 비유):

원래 R12-C plan 은 21 단계 (T0~T20) 로 짜여 있었음. T11 까지 land 해보니 *직원이 회의에서 합의에 도달하는 진행 절차* (이전 12 단계 합의 진행) 가 새 사무실 구조 (부서별 회의실 + 직원 능력 분리) 와 잘 안 맞음. 사용자 + 직원들 토론 결과 — 진행 절차를 통째로 바꾸기로 결정 (의견 카드 트리 + 일괄 동의 투표).

이 결정이 T12 이후의 작업 정의 (회의 흐름 / 합의 인식 / 부서별 화면) 를 광범위하게 흔들기 때문에, *T0~T11 + 정리 + 멤버 표시 fix* 까지를 **1차로 끊어 main 에 정식 land**, *회의 진행 재설계 본체* 는 **R12-C2 라는 새 phase 에서 처음부터 다시** 진행하는 게 회귀 분리 + 안정 측면에서 안전.

## R12-W — 채널 단위 파일 권한 wire-up (진행 중, 2026-05-12)

worktree `feat/r12-c2-redesign-r2` (R12-C2 와 평행 phase). R12-C2 P6 dogfooding 진입 가이드 (`7c39e92`) 위에서 시작.

**Why (사무실 비유):** 회의 채널에 들어온 AI 직원이 사장이 요청한 spec 문서를 *읽으려 시도조차 하지 않고* "본 회의 채널 규칙상 파일을 직접 읽지 못해" 라고 자기검열하던 회귀. 인사팀이 모든 직원에게 빈 권한 쪽지 ("파일 접근 금지") 를 일률적으로 발급하던 게 원인 — 직원별 권한 양식은 설계만 있고 인사팀과 wire 가 안 돼 있었음.

**해결 방향:** 권한 단위 = 채널 (부서 = 기본 채널의 라벨). 채널 row 에 5 axis boolean 컬럼 (file_read / file_write / command_exec / web_search / db_read) 을 직접 박고, 기본 채널은 SKILL_CATALOG default 로 자동 채움. 사용자는 채널 설정 모달에서 부서 template + 미세조정.

## R12-X — spec §7.6 PathGuard 봉인 chain 복원 (진입 예정, 2026-05-12)

worktree 미결정 (R12-W 와 동일 worktree 가능 / 별 worktree 분리 가능 — R12-W 종결 후 결정).

**Why (사무실 비유):** R2 시점에 설치된 "사방 벽" (PathGuard) 이 정작 *입구를 막아본 적이 없는* 형태였음. 사장이 직원들에게 "사무실 안에서만 일하라" 고 약속했지만, 직원들은 사실상 *건물 어디든 갈 수 있었다*. 사장이 dogfooding 으로 그 사실을 발견.
